# L2 / L3 boundary — wyrd-f295

Where the JSONL-as-source-of-truth contract draws the line. **L2** is
the per-source curated JSONL in `data/mining/<source_id>.jsonl` — the
source of truth, committed to git. **L3** is the SQLite query index
at `~/.wyrd/lexicon.db` — a rebuildable build artifact.

For a higher-level overview of the four-layer pipeline (L1 raw inputs
→ L2 curated JSONL → L3 SQLite → L4 runtime bundle) see the migration
plan at `/home/devon/.claude/plans/mellow-nibbling-kazoo.md`.

This doc is the operator's quick-reference: which tables / columns are
L2 (preserved through dump/build round-trip) vs L3 (regenerated by
enrichment passes and never written by `dump-jsonl`).

## L2 — source-attributable facts (dumped + replayed)

### `source`
The bibliographic record. One row per source, dumped as a canonical-
state `source` row at the top of every `data/mining/<id>.jsonl` file.
The file's source row is the source_id for every list-type row in
the same file (citations, descent edges, etymology elements,
mining-run audits).

### `etymon` (L2 columns only)
Source-attributable: `canonical_form`, `language`, `modifier_type`,
`position_pref`, `notes`, `pronunciation_ipa`, `pronunciation_dialect`,
`original_script`, `transliteration`. Plus the joined many-to-many
tables `etymon_gloss` and `etymon_tag` (folded inline as `glosses`/
`tags` array fields on the dumped canonical-state row).

Cross-file ref: `<language>:<canonical_form>` (e.g.
`old-english:cot`). Same ref across multiple source files = same
entity; build merges (glosses + tags unioned, scalar fields
last-write-wins by file order).

### `etymon_citation`
Dumped as `citation` list rows. The `source_id` FK is implicit from
the JSONL file the row lives in; the row carries `etymon_ref` +
optional `page` / `short_quote` / `context_snippet`.

### `etymon_descent`
Dumped as `etymon_descent` list rows. Carries `parent_ref` +
`child_ref` + `edge_type` + `source_id` (implicit) + optional
`confidence` / `notes`. Build requires both referenced etymons to
exist (in this file or any other file in the dir).

### `mining_run`
Dumped as `mining_run` list rows. Per-source audit log: `provider`,
`model`, `mode`, `parsed_count`, `accepted`, `declined`, `rejected`,
plus optional timestamps and `by_failure` JSON.

### `toponym`
Dumped as canonical-state `toponym` rows. Carries `modern_name` +
optional `country` / `region`. Cross-file ref:
`<modern_name>@<region>` (with `-` when region is null).

### `toponym_etymology` + `toponym_etymology_element`
Dumped together as a single `etymology_element` list row per scholar's
breakdown, with the ordered element list inline. Carries
`toponym_ref` + optional `page` / `historical_form` / `confidence` /
`notes` / `attested_year`, and an `elements` array of
`{ordinal, etymon_ref, inflection?, surface_in_modern?}`.

### Deferred (planned L2, currently skipped)

- **`toponym_attestation`**: free-text `source_doc` field has no FK to
  `source`. Phase 1 task: parse `source_doc` strings + bucket per
  source so they can be dumped per-file.
- **`etymon_text_match`**: scholar-attributed text matches (loose
  evidence). Phase 1 task once a method-filter distinguishes scholar
  matches from auto-fuzzy matches.
- **`etymon_variant`** (wiktextract forms-mining): Phase 3a task once
  the forms-mining ingester is re-cut to emit JSONL events.

## L3 — derived (regenerated by enrichment passes, never dumped)

### Etymon-table L3 columns
- `lemma_id` — set by `lexicon link-lemmas` (D29 inflection clustering)
- `lemma_method` — provenance tag for the link-lemmas method version
- `inflection` — set by link-lemmas alongside `lemma_id`
- `merged_into_id` — set by `lexicon cluster-ocr-variants` (D22 OCR
  clustering)
- `cognate_id` — set by `lexicon cluster-cognates` (D27 / wyrd-0ug)
- `cognate_method` — provenance tag for cluster-cognates version
- `english_shaped` — set by `lexicon shape-english` (Phase 2b)
- `stratum` — set by `lexicon classify-stratum` (wyrd-lr4)

These are all enrichment-derived columns. `lexicon
rebuild-from-jsonl` leaves them NULL; operators run the relevant
enrichment commands after rebuild.

### Derived tables (rebuilt by enrichment passes)

- `reflex` + `reflex_etymon` — modern surface-form mapping. Populated
  during seed (`lexicon build` from meanings.json) and never updated
  thereafter; consider whether this stays L3 or moves to L1.
- `toponym_decomposition` — matcher output (wyrd-08m). Re-derivable
  from `etymon` + bundled `meanings.json` by re-running
  `lexicon decompose`.
- `etymon_meaning_synset` — LLM classification (wyrd-44a /
  meaning_synset layer). Re-derivable by re-running the LLM-classify
  pass.
- `etymon_period_form` — period-form projection (wyrd-skm Phase 3.0b).
  Re-derivable by re-running `lexicon project-period-forms`.

### Views (always derived)

- `etymon_canonical`, `etymon_consensus` — SQL views over the etymon
  table. Auto-rebuilt with schema init.

## Build canary

The `mining_run` row type is the audit signal. Any L3 derived row
whose enrichment-pass run isn't recorded in the L2 mining_run set
fails the build — caught by a validation pass at the end of
`lexicon rebuild-from-jsonl` (planned, not yet implemented).

## L3 enrichment passes — canonical order

Per wyrd-ilam (Phase 2a), these are the L3 enrichment passes that
operate against the post-replay DB. Each writes specific columns on
`etymon`; the column → pass mapping is fixed so `lexicon
enrichment-status` can report coverage. Order matters where columns
chain through other columns (link-lemmas needs canonical merged_into_id
state, project-period-forms needs lemma_id state, etc.).

| Pass | Writes | Method version | Migrated |
|------|--------|----------------|-----------|
| `normalize-ocr` | `merged_into_id` | `cluster-ocr-v1` | ✅ wyrd-ilam |
| `link-lemmas` | `lemma_id`, `inflection`, `lemma_method` | `link-lemmas-v1` | ✅ wyrd-ilam |
| `apply-curation` | overrides any of the above per operator decision | `manual-curation-v1` | ✅ wyrd-2jhs |
| `decompose` | (`toponym_decomposition` table) | matcher rules | ✅ wyrd-hidb |
| `cluster-cognates` | `cognate_id`, `cognate_method` | `cluster-cognates-v1` | ✅ wyrd-hidb |
| `classify-stratum` | `stratum` | hardcoded heuristics | ✅ wyrd-hidb |
| `derive-english-shaped` | `english_shaped` | hardcoded rules | ✅ wyrd-hidb |
| `project-period-forms` | (`etymon_period_form` table) | hardcoded rules | ✅ wyrd-hidb |

All eight passes run via `run_full_enrichment` in canonical order
(`lexicon enrich` and `lexicon rebuild-from-jsonl --with-enrichment`).
Each pass keeps its standalone CLI command for targeted reruns
(e.g. with `--force`).

## Curation event log (wyrd-2jhs)

`data/mining/_curation.jsonl` holds operator overrides applied AFTER
the auto-clustering passes. Each row is an `etymon_curation` event
with `ref` (the curated etymon) plus optional `lemma_ref` /
`merged_into_ref` / `inflection` / `reason` fields.

### Row semantics

- `lemma_ref: "<language>:<canonical_form>"` — set the curated
  etymon's `lemma_id` to point at this etymon. Also clears
  `merged_into_id` (the curated row stays canonical) and stamps
  `lemma_method='manual-curation-v1'`.
- `lemma_ref: null` — explicitly clear the curated etymon's
  lemma_id / inflection / lemma_method. Distinguishes "no override
  on this column" (key absent) from "operator wants this cleared"
  (key present with null value).
- `merged_into_ref: "<language>:<canonical_form>"` — set
  `merged_into_id` (OCR-cluster tombstone target). Also clears
  `lemma_id` (a tombstone shouldn't claim a lemma role).
- `merged_into_ref: null` — clear the merge tombstone.
- `inflection`, `reason` — informational; ride along with
  `lemma_ref` when set.

### Operator workflow

```bash
# Surface what auto-clustering chose for a suspect etymon.
lexicon browse etymon "old-english:caelf"

# Record the override.
lexicon curate-etymon "old-english:caelf" \
  --lemma-ref "old-english:cealf" \
  --inflection spelling_variant \
  --reason "scribal æ/ae per dead-rando audit (wyrd-lene)"

# Apply (alongside the auto-clustering passes).
lexicon enrich --apply

# Verify.
lexicon browse etymon "old-english:caelf"
```

Curation events are tracked in git like any other L2 file — `git
blame data/mining/_curation.jsonl` shows who curated what and when.
Reverting an event is appending another event with the cleared
value (`lemma_ref: ''` via the CLI), preserving the audit trail.

## Prune commands — toponym + etymon row removal

`lexicon prune-toponym` (wyrd-lene) and `lexicon prune-etymon`
(wyrd-8wgr) append `_op: remove` events to a source's L2 JSONL file
for the named row. Each validates that the ref actually resolves in
the source file before writing (typo-safe) and stamps an optional
operator `_reason` for git-blame audit.

```bash
# Audit first — confirm the row is actually wrong:
lexicon browse toponym "Cart@Herefordshire"
lexicon browse etymon "old-english:pīe"

# Prune:
lexicon prune-toponym "Cart@Herefordshire" bannister_1916_herefordshire \
    --reason "wyrd-lene: 'Cart.' is the Cartulary abbreviation"
lexicon prune-etymon "old-english:pīe" rando-port \
    --reason "wyrd-8wgr: BT says peach-tree, not gnat"

# Rebuild — orphaned fact-rows skip + count in the build telemetry:
lexicon rebuild-from-jsonl
```

On rebuild, fact-rows referencing the pruned entity (citations,
descent edges, etymology elements naming a removed etymon; etymology
elements naming a removed toponym) count into `*_orphans` /
`*_orphan_refs` and skip the insert rather than raising. Operators
see the orphan counts in the rebuild summary so unexpected typos
(vs. expected post-prune orphans) are still visible.

## Operator workflow

### Editing L2 (the source of truth)

1. Run a mining command (e.g. `lexicon mine-skeat`, `lexicon
   ingest-domesday`). Writes happen against the L3 SQLite directly
   today; Phase 3 tickets convert ingesters to emit JSONL events
   directly.
2. After mining, dump back to JSONL:
   `lexicon dump-jsonl --source-id <id>`. Commits the file in git.

### Rebuilding L3 from L2

One-shot rebuild — `--with-enrichment` runs the full 8-pass chain
(wyrd-hidb):

```bash
lexicon rebuild-from-jsonl --db ~/.wyrd/lexicon.db --jsonl-dir data/mining \
    --with-enrichment
lexicon export-meanings --output wyrd/generators/kenning/data/meanings.json
```

Or step-by-step:

```bash
lexicon rebuild-from-jsonl --jsonl-dir data/mining
lexicon enrich --apply              # runs the full chain by default
lexicon enrichment-status           # verify coverage
# Or invoke individual passes (e.g. to re-run with --force):
lexicon classify-stratum --apply --force
```

### Pre-release drift check (wyrd-w3x0)

Before re-exporting the committed `wyrd/generators/kenning/data/meanings.json`,
run `diff-bundle` to see what the rebuild would change:

```bash
lexicon diff-bundle           # uses defaults: data/mining/ + committed bundle
# Exit 0 = byte-identical (safe re-export, or no re-export needed).
# Exit 1 = drift → structured summary names added/removed/changed
#          subjects + first byte divergence window.
```

`diff-bundle` rebuilds into a temp DB, exports, and diffs. It pairs with
`diff-rebuild` (which compares L2 row counts only): `diff-rebuild`
catches JSONL pipeline regressions; `diff-bundle` catches export-side
drift the row counts wouldn't surface.

### Manual curation (post-Phase-3 pattern)

When ingesters emit events (Phase 3 work), curation flows as:

```bash
# Edit the JSONL file directly — append a patch event:
echo '{"_op":"patch","_type":"etymon","ref":"oe:cot","glosses_remove":["wrong"]}' \
  >> data/mining/skeat.jsonl
# Compact when the curation pass is done:
lexicon compact-jsonl data/mining/skeat.jsonl
# Rebuild:
lexicon rebuild-from-jsonl
```

## Bulk sources (wyrd-0vj3)

The L1 wiktextract slices live OUTSIDE the L2 JSONL pattern — they
are too large to commit to git and too noisy to round-trip through
the per-source dump path. Storage workflow:

* **Manifest:** `data/mining/_bulk_manifest.json` in git. Tiny —
  lists each slice with its `s3_key`, `sha256` (integrity check),
  and size metadata.
* **S3 bucket:** `s3://521studios-staging-wyrd-lexicon-bulk/`,
  region `us-east-2`. Versioning enabled — S3 history is the
  rollback source-of-truth. See
  `infra/terraform/modules/wyrd-lexicon-bulk` for the terraform
  module.
* **Local cache:** `~/.wyrd/sources/`. Lives outside the repo's
  working tree, so no .gitignore entry. Mirrors the bucket's key
  prefix; holds zstd-compressed `.jsonl.zst` slices.
* **Config:** `~/.wyrd/config.toml`. Bucket / region / AWS profile
  / local cache dir; env vars (`WYRD_BULK_BUCKET` etc.) override.

Operator workflow:

```bash
# First run on a fresh checkout — populate local cache from S3:
lexicon fetch-bulk-sources

# After mining a new slice locally — push to S3 + update manifest:
lexicon push-bulk-sources

# Check whether local cache matches the manifest:
lexicon verify-bulk-sources
```

`lexicon ingest-wiktionary` reads `.jsonl`, `.jsonl.gz`, and
`.jsonl.zst` transparently — the bulk cache form is `.jsonl.zst`.

Per the wyrd-0vj3 plan (`docs/plans/wyrd-0vj3.md`): staging-only,
single-user dev asset, no IAM policy in the terraform module. The
companion ticket `wyrd-hidb` wires this into a single-command
`rebuild-from-jsonl` flow.
